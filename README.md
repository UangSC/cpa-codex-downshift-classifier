# Codex 降档检测与分类插件

基于 Go 原生插件和 React 管理页面，通过 CLIProxyAPI（CPA）官方宿主接口检测 Codex 凭证，记录回答与判定依据，并按凭证管理分组前缀或优先级。

**当前为开发中的源码预览。** 插件版本见 [package.json](package.json)，可构建 Linux amd64、Linux arm64 和 Windows amd64 三种插件包。

## 功能

- 使用糖果题检测指定 Codex 凭证，要求模型以单行 `{"ANSWER":21}` 格式回答；目前的判定仍接受包含独立数字 `21` 的有效回答。
- 可切换模型指纹：随机采集三份有效数字序列，合并计算参考库归因概率；目标参考匹配且目标概率严格大于 **90%** 才算正常，等于 90% 也不通过。默认方式仍为糖果题。
- 通过 CPA Codex 执行器复用现有认证和代理，锁定目标凭证，读取完整流式响应后判定。
- 支持手动、批量和定时巡检，提供有限重试、取消任务、排除凭证和持久化历史。
- 概览可直接切换糖果或指纹检测，巡检并发支持 1～9、默认 4；刷新额度按钮查询当前页凭证，同时最多刷新 2 个。
- 支持分组前缀或优先级管理；凭证权重默认读取 CPA 当前值，启用加权轮询后可逐个修改。
- 提供低、中、高三档思考程度和可保存的请求头覆盖，默认请求身份以 Codex CLI `0.170.0` 为基线。
- 管理页面使用真实服务端状态，包含多种布局、分页、额度观察、同步状态和巡检确认。
- 手动追加巡检会并入进行中的批次，沿用首次开始时间。历史和任务面板默认展开最近批次。
- 统计页可按模型查看近七天的每日巡检结论、糖果题答对率和指纹样本有效率，数据来自已保留的巡检证据。

糖果题和模型指纹均属于行为检测，不能证明真实模型身份。指纹沿用参考插件的冻结数字挑战库、排序器和概率校准；`gpt-6.1-sol` 按参考库明确登记映射到 `gpt-6-astra` 候选。未收录模型、不足三份有效样本或无可靠概率时保持不确定。来源和许可见 [第三方说明](THIRD_PARTY_NOTICES.md)。

## 快速开始

已验证宿主为 CPA `8.0.63`，原生接口为 C ABI 1 / RPC schema 6。源码构建需要 Go 1.23+、Node.js 20.19+（20.x）或 22.12+、pnpm，以及支持 CGO 的 C 编译器。

```powershell
pnpm install --frozen-lockfile
./scripts/build.ps1 -GoExe <go.exe路径> -Compiler <gcc.exe路径>
```

构建脚本编译页面、准备嵌入资源、运行 Go 静态检查，再生成对应的 DLL 或 SO。三平台构建、版本校验及打包见 [开发与部署](docs/development.md)。

安装到本机 CPA：

```powershell
./scripts/deploy-local.ps1 -CoreDir <CPA核心目录> -GuiConfig <EasyCLIProxyAPI配置文件>
```

也可使用进程变量 `CPA_DOWNSHIFT_MANAGEMENT_KEY` 提供管理密钥。部署脚本通过官方配置 API 更新本插件，备份配置和状态，验证加载路径、版本及内核哈希。详细步骤见 [开发与部署](docs/development.md)。

管理页面路径：

```text
/v0/resource/plugins/cpa-codex-downshift-classifier/ui
```

## 代码结构

| 目录 | 职责 |
| --- | --- |
| `cmd/downshift/` | 原生 ABI、插件注册、配置和管理接口桥接 |
| `internal/cpa/` | 官方管理接口、凭证状态、定向模型执行与流解析 |
| `internal/classifier/` | 检测规则、任务、分类、调度和持久化 |
| `internal/fingerprint/` | 三次数字挑战、冻结参考数据与模型概率计算 |
| `src/api/` | 同源认证与服务端 API 客户端 |
| `src/store/` | 页面状态、异步操作和设置草稿 |
| `src/components/` | 业务组件与通用界面组件 |
| `src/views/` | 概览、统计、历史和设置页面 |
| `src/inspection/`、`src/lib/` | 检测方式描述与页面纯函数 |
| `web/` | 构建后页面资源的 Go 嵌入入口 |
| `scripts/` | 构建、部署和 CPA 请求头配置工具 |
| `docs/` | 架构、API 与开发说明 |
| `examples/` | 不含密钥的配置示例 |

新检测规则放在后端分类层，CPA 接口适配放在 `internal/cpa/`，页面只提交任务并展示结果。职责与扩展位置见 [架构说明](docs/architecture.md)，请求结构见 [API 文档](docs/api.md)。

## 已知边界

- 配置写入通过官方字段 PATCH 完成；多个凭证之间不构成事务，同一字段的外部并发写入不具备 CAS 保证。
- 频繁的真实 502/503/429 参与降档：默认单轮累计 3 次，或连续 2 轮未完成检测并出现这些错误。401/403、本地冷却与网络异常保留独立原因。默认重试至少等待 5 秒、10 秒，CPA 官方冷却更长时等待其到期，详情记录每次请求和实际等待。
- 额度采用 CPA 被动观察或通过官方管理接口主动查询，按观测时间选择更新数据，缺少可靠数据时显示未知；会话数与真实模型指纹也不模拟。
- 插件使用官方内部执行入口，未经过普通 `/v1/responses` HTTP 日志入口。本次核实的桌面宿主会拒收缺少 `request_id` 的后台用量记录；插件历史中的回答、用量及判定不受该显示问题影响。
- 状态、认证配置、构建产物、临时诊断和本地测试资料均不属于源码发布范围。
