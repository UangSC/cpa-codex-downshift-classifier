# Codex 降档检测与分类插件

CLIProxyAPI 的 Codex 凭证巡检前端：用**糖果题**和**模型指纹**探测凭证，判断是否疑似被路由到能力更低的模型，并把结论落到分组前缀上（正常默认**不加前缀**，降档默认 `downshift/`，两者都可在设置中修改）。

- 判定按**凭证**计算。一个 Codex 账号降智后，它暴露的所有模型名都会一起降智，因此分组前缀作用于该凭证的全部模型，界面只呈现一个检测模型，不逐个模型展示。
- 检测证据按「凭证 × 检测模型」记录：一轮检测的题目、回答、指纹比对、重试与分组写入结果都可以展开查看。
- 结论与分组写入是两件事：判定完成但写不进凭证文件时，界面显示「待同步 · 重试」。

> 当前版本使用**模拟数据与模拟检测流程**，不会调用 CLIProxyAPI，也不会改动真实凭证文件。界面顶部右侧常驻「模拟数据」标记；接入真实后端后会自动显示「实时数据」。

## 快速开始

```bash
pnpm install
pnpm dev        # http://127.0.0.1:5273（端口被占用时自动顺延）
```

生产构建：

```bash
pnpm build      # 先 tsc --noEmit，再输出 dist/
pnpm preview    # 本地预览构建产物
```

构建产物是纯静态资源，`vite.config.ts` 使用相对 `base`，可直接作为 CLIProxyAPI 插件的浏览器资源页发布（`/v0/resource/plugins/cpa-codex-downshift-classifier/…`）。

要求 Node.js 20+。当前依赖：React 19、zustand 5、Vite 8、TypeScript 7。

## 怎么用

### 三种布局

工具栏右侧切换，选择会保存：

| 布局 | 适合 | 密度 | 选择方式 |
| --- | --- | --- | --- |
| **列表** | 一屏浏览全部凭证 | 紧凑表格，行高统一 | 行首复选框 |
| **卡片** | 关注状态与近期曲线 | 宽屏每行 3–5 张，同排卡片等高 | 点击卡片（边框高亮 + 显示勾选） |
| **三栏** | 按正常 / 不确定 / 降档分池排查（默认布局） | 每栏 2 列 × 4 行，每页最多 8 张卡片 | 点击卡片 |

切换布局带淡入位移动画。三栏每栏高度一致、内部为 2 列网格，每页最多 8 张卡片，底部提供「上一页 / 下一页」分页，内容不会把某一栏拉长；未检测的凭证归入中间一栏，用中性色和「未检测」标签区分，不会被当成不确定。

### 一眼看懂

- **统计卡片**按凭证计数，点击即筛选；再点一次取消。卡片计数取该凭证最近一轮检测的判定；分组状态在列表里单独展示（两者可能不同，例如「判定未完成、分组保持原样」）。
- **近期状态灯**左侧更早、右侧更近，每一格是一轮检测：
  - 绿：该轮完整通过
  - 黄：不确定（证据不足、待确认，或错误后的重试过程）
  - 红：降档（答案不符、指纹异常，或重复 502/503 达到判定条件）
  - 空心格：未完成（取消 / 认证或额度导致未能执行），不等于正常
  - 悬停、键盘聚焦或点击任意一格，可查看时间、测试方式、判定原因、尝试次数与后续分组动作。
- **凭证状态**：`认证失效`、`额度不足`、`会话中`、`额度未知` 都有文字标注，且不会被当成降档。
- **分组**：判定结论与当前分组分开表达。列表里直接显示实际生效的模型名前缀（正常默认显示「无前缀」、降档显示 `downshift/`）和覆盖的模型数，悬停可看说明；写入失败时换成「↻ 待同步 · 重试」文字链接。
- 提示信息统一用小型磨砂气泡，不占用页面空间。**黄色 / 红色状态灯**的气泡带错误详情：点击固定，鼠标移出约 1 秒后自动淡出，期间把鼠标移回来会取消关闭；绿色 / 空心灯点击直接打开完整依据。
- 卡片与面板使用高斯模糊玻璃质感（毛玻璃 + 高光渐变），页面底色为左下淡蓝、右上淡绿的清新渐变。

### 操作

- 单个复测：凭证行/卡片上的「复测」。
- 批量：勾选后底部出现操作条；或直接「巡检全部符合条件」（只包含满足额度与状态条件的凭证）。
- 依据：打开某一轮的完整证据（判定、回答、指纹比对、请求与重试、分组写入、免责说明）。题目原文与数字挑战默认折叠，需要时再展开。
- 演示场景：用可重复的模拟情景逐条验证判定规则（见下文）；运行后会关闭面板并自动打开任务面板。
- 任务面板：右上角「任务」，查看排队、等待空闲、重试、跳过、取消的对象与原因，并可停止任务。
- 键盘：`/` 聚焦搜索；`Esc` 关闭浮层（只关最上层，焦点回到触发处）；浮层内 `Tab` 在面板内循环，不会跑到页面背后。

## 判定规则

| 情况 | 结论 | 分组 |
| --- | --- | --- |
| 所选测试全部通过 | 正常 | 恢复原始模型名（正常前缀默认为空，可在设置中配置） |
| 糖果题回答中没有独立的 `21` | 降档 | 写入降档前缀 |
| 指纹与参考库差异显著（更接近其它参考模型） | 降档 | 写入降档前缀 |
| 指纹有效样本不足 | 不确定 | **保持不变** |
| 首次 502/503，重试后成功且本轮测试全部通过 | 正常 | 恢复正常分组（默认不加前缀），保留错误与重试记录 |
| 502/503 重试耗尽，且未达重复失败轮数 | 不确定 | **保持不变** |
| 连续 N 轮都出现 502/503（502 与 503 交替同样计入） | 降档 | 写入降档前缀 |
| 认证失效 / 额度用尽 / 排队 | 未能检测 | **保持不变**，按状态问题提示 |
| 任务被取消 | 未完成 | **保持不变**，不记作正常 |
| 判定完成但写入失败 | 结论正常显示 | 显示待同步，分组仍是旧值 |

要点：

- 一轮检测只在结束时提交结论；轮内某次请求成功不会覆盖已经达成的降档判定。
- 恢复需要**新一轮完整检测通过**；历史降档记录继续保留在状态灯与历史页。
- 糖果题答案判定是格式宽容的：只要求出现独立的数字 `21`，中文叙述、单位、标点都不影响，`213`、`21.5` 之类不算。

### 默认设置

账号名默认不脱敏，可用列表上方的眼睛按钮切换模糊显示。默认布局为三栏。

| 项 | 默认值 | 可改 |
| --- | --- | --- |
| 正常组前缀 | 空（不加前缀） | 任意前缀 |
| 降档组前缀 | `downshift/` | 任意前缀 |
| 检测模型 | `gpt-6.1-sol` | 任意模型名 |
| 测试项目 | 糖果题 + 指纹 | 任选其一或两者 |
| 最大重试次数 | 2 次（共尝试 3 次） | 0–4 |
| 首次等待 / 退避倍数 | 2 秒 / ×2（即 2s、4s） | 0.5–5 秒、×1–×3 |
| 重复失败判定 | 连续 2 轮 | 2–4 轮 |
| 额度门槛 | 剩余额度**高于** 15% | 0–100% |
| 额度未知时 | 仍然检测 | 改为跳过 |
| 检测并发 | 3 个凭证 | 1–6 |
| 定时巡检 | **关闭**（不定时） | 按间隔或每天定时 |

设置页会把当前配置翻译成一句可执行的规则说明，与实际行为同源（`src/lib/rules.ts`），不会出现文案与实现不一致。

额度口径：取该凭证**所有已知额度窗口中剩余比例最低的一个**，严格大于阈值才检测；等于阈值不检测。额度未知时按设置处理，并在卡片上明确标注。

忙碌处理：会话中的凭证排在空闲凭证之后，并在同一任务内等待，`~4 秒`后模拟会话结束继续执行——不会新建第二个任务，也不会打断正在使用的会话。

## 与 CLIProxyAPI 的接入边界

已核对 CLIProxyAPI 当前提供的插件能力，本前端按以下真实机制设计：

1. **Management API capability**：插件注册 `Routes`（暴露在 `/v0/management/...`，需要管理密钥）和 `Resources`（浏览器资源页，路径为 `/v0/resource/plugins/<pluginID>/...`）。本页面即资源页。
2. **Model Registrar capability**：插件通过 `model.register` 注册模型 ID。`downshift/gpt-6.1-sol` 就是注册出来的模型 ID，由插件路由到对应凭证池；因为注册以凭证为单位，一次分组决定会同时移动该凭证的全部模型。

### 前端侧已就绪的接口约定

`src/api/contract.ts` 定义了完整契约（类型 + 端点 + 鉴权方式）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/v0/management/plugins/cpa-codex-downshift-classifier/snapshot` | 凭证、按模型的证据、设置 |
| POST | `…/checks` | 发起检测（凭证集合、模型、测试项目、范围） |
| GET | `…/tasks/:id` | 任务与排队/等待/重试明细 |
| POST | `…/tasks/:id/cancel` | 取消任务 |
| POST | `…/sync` | 重试凭证文件的分组写入 |
| PUT | `…/settings` | 保存设置 |

鉴权使用 `Authorization: Bearer <management key>`。同源部署时资源页可复用管理面板已保存的密钥（`readStoredManagementKey()` 会尝试常见键名），也可以由宿主注入：

```js
window.__CPA_DOWNSHIFT__ = { apiBase: 'http://127.0.0.1:8317', managementKey: '...' }
```

注入后 `createBackend()` 自动切换到 HTTP 实现，组件无需改动。

### 还需要后端完成的部分

- 真实的糖果题 / 指纹检测执行、重试与证据采集（当前由 `src/store/engine.ts` 模拟）。
- 凭证文件的分组前缀写入，以及写入失败时的错误透传（当前模拟 `EBUSY`）。
- 额度窗口、忙闲状态、认证状态的实时来源。
- 定时巡检在服务端触发（当前前端定时器仅用于演示；关闭后不再产生任务）。

## 项目结构

```
src/
  api/            backend 契约、mock 与 HTTP 实现、传输选择
  data/seed.ts    模拟数据（凭证、证据、行为表、默认设置）
  lib/            纯逻辑：格式化、前缀校验、规则文案、派生视图
  store/          zustand 状态、模拟检测引擎、定时器、演示场景
  components/     UI 原子组件、凭证三种布局、证据抽屉、任务面板、演示面板
  views/          概览、历史、设置
  styles/         设计变量与样式（浅色 / 深色）
```

模拟检测引擎与真实接入点都集中在 `src/store/engine.ts` 与 `src/api/`，替换这两处即可完成对接。

## 已验证

- `pnpm typecheck`、`pnpm build` 通过。
- 浏览器实测（1920×1080，另抽查 1440×900 / 1280×800，无横向溢出）：
  - 默认未启用定时任务；开启后显示下一次执行时间，关闭后不再产生新任务，正在执行的任务不受影响。
  - 批量巡检按设置的并发数（默认 3）并行执行；会话中的凭证先等待空闲，在同一任务内继续，不会新建任务；额度低于阈值与认证失效的对象被跳过并写明原因。

  - 判定完成但分组写入失败时显示「待同步 · 重试」，重试仍失败会再次提示；修改前缀后预览与已分组凭证的模型名一致。

## 说明

- 账号名称默认完整显示；工具栏的**眼睛按钮**会把所有账号名做高斯模糊，便于截图或共享屏幕，再点一次即可还原（仅影响显示，不改数据）。界面从不展示完整密钥或访问令牌。
- 行为测试只能说明「本轮回答与参考分布的接近程度」，不能确认底层实际模型身份；界面文案始终按此表述，不会直接断言真实模型。
- 页面按 2K 桌面宽度设计，未针对手机端做专门适配。
